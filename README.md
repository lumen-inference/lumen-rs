# lumen-rs

**lumen-rs** — движок инференса больших языковых (LLM) и мультимодальных моделей на Rust и CUDA C++, спроектированный для **гибридного выполнения (offloading)**: когда модель не помещается в видеопамять одной потребительской видеокарты (16–32 ГБ VRAM), часть её весов и состояний размещается в системной памяти (RAM) или на NVMe-накопителе, а вычисления распределяются между GPU и CPU.

Documentation: **[Русский (docs/RU/)](docs/RU/architecture.md)** · **[English (docs/EN/)](docs/EN/architecture.md)**

## Ключевые архитектурные свойства

1. **Компилятор статического плана (`Program`).**
   При загрузке модели описание её архитектуры и конфигурация размещения один раз компилируются в неизменяемую структуру `Program`, где каждому оператору заранее назначены устройство счёта, буферы в памяти, стримы CUDA и точки синхронизации. В горячем цикле генерации нет аллокаций памяти, поиска по именам и динамического ветвления по устройствам.
2. **Четырёхуровневая модульность.**
   - **Архитектуры моделей (`lumen-models`):** схемы семейств (`Llama`, `Qwen3`, `Qwen3-Next` / `Qwen3.5`, `Qwen3.8-Flash-Next`, `Gemma 4`, `gpt-oss`), собираемые из общих модулей.
   - **Архитектурные модули (Modules):** строительные блоки слоёв — `FullAttention`, `SlidingAttention`, `SparseAttention` (QSA), `GatedDeltaNet` (GDN), `DenseMlp`, `MoE`, `PLE`, `HyperConnections`.
   - **План размещения и планировщик (`lumen-config`, `lumen-exec`):** связывает дерево модулей модели с местами хранения (`vram`, `ram`, `disk`) и устройствами счёта (`cuda`, `cpu`), автоматически вставляя операторы пересылки (`Transfer`) и упреждающего чтения с диска (`Fetch`).
   - **Вычислительные бэкенды (`lumen-cpu`, `lumen-cuda`, `lumen-ref`):** реализуют единый интерфейс `trait Executor` и исполняют закрытый набор элементарных операторов (`Op`).
3. **Низколатентная синхронизация GPU ↔ CPU в едином адресном пространстве.**
   GPU и CPU обмениваются данными через закреплённую память (`pinned RAM`) с аппаратной синхронизацией на стримах (`cuStreamWriteValue32` / `cuStreamWaitValue32`) и пользовательским спин-пулом потоков CPU. Это позволяет захватывать шаг генерации вместе с CPU-оффлоадом в единый **CUDA Graph** и перекрывать вычисление маршрутизируемых экспертов на CPU с вычислениями на GPU.
4. **Решётчатый формат квантования LTQ (Lumen Trellis Quant).**
   Формат сжатия весов до 2–5 бит на основе решётчатого кодирования Унгербёка (TCQ) на тайлах $16 \times 16$ с входным преобразованием Адамара, дробными скоростями (`D2`, `D4`) и распределением битности по срезам строк на основе информации Фишера.
5. **Оценка производительности от физического потолка оборудования ($\eta$).**
   Планировщик рассчитывает аналитическую нижнюю границу времени шага (`Program::floor`) по пропускной способности VRAM, DRAM, шины PCIe и задержкам синхронизации конкретного стенда, оценивая эффективность как $\eta = t_{\text{floor}} / t_{\text{measured}}$.
