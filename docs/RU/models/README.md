# Справочник архитектур моделей

[English](../../EN/models/README.md)

Начните с [общего описания блоков](../blocks.md), чтобы понять, как эти механизмы соединяются в модель. Здесь собраны различия конкретных семейств и точные параметры для их реализации. Определения общих терминов — в [словаре](../glossary.md).

Это справочные описания семейств и требований к их реализации, а не список работающих моделей. Новый движок на C17 собирает модели из общих блоков; первыми вычислительными бэкендами будут CPU и Vulkan. Целевые правила композиции и владения определены в [blocks.md](../blocks.md) и [architecture.md](../architecture.md), граница устройства — в [backends.md](../backends.md). Названия модулей ниже описывают их смысл, а не публичные C-типы.

Семейство описывает порядок слоёв и параметры общих блоков. QSA не является универсальным sparse attention; для другого алгоритма нужен собственный состав операций. Размеры состояния и способ доступа к памяти определяются параметрами модели и возможностями устройства.

Подробное описание семейств со специализированными модулями вынесено в отдельные файлы:

- **[qwen3_next.md](qwen3_next.md)** — гибридное семейство `qwen3_next`, `qwen3_5_dense` (`qwen3_5`) и `qwen3_5_moe` (чередование 3:1 линейного внимания `Gated DeltaNet` и полного внимания с гейтом).
- **[qwen4_exp.md](qwen4_exp.md)** — архитектура `qwen4_exp` (`Qwen3.8-Flash-Next`: разреженное внимание `QSA`, 4-поточные остаточные связи `Hyper-Connections` и таблица n-грамм `PLE`).
- **[gemma4.md](gemma4.md)** — семейство `Gemma 4` (реконструкция $K = V$, пропорциональный `p-RoPE`, общий KV-кэш на финальных слоях, `PLE` и параллельная работа плотного MLP с MoE).

## 1. Базовые архитектурные модули

Слои трансформерных и гибридных моделей строятся из следующих типовых модулей:

| Категория | Модуль | Назначение | Где используется |
| :--- | :--- | :--- | :--- |
| **Работа с контекстом (Sequence Mixers)** | **`FullAttention` / `SlidingAttention`** | Причинное внимание по всему контексту или по скользящему окну последних $W$ токенов. Ресурсы состояния и их представление, в том числе страничное, задаются явно. | Все семейства моделей |
| | **`SparseAttention` (QSA)** | Разреженное внимание с индексатором: перед основным вниманием лёгкий индексатор оценивает блоки по 4 токена и выбирает $\le 512$ релевантных блоков. Размещение основного кэша в RAM требует поддержанного пути выборки и передачи данных. | `Qwen3.8-Flash-Next` (`qwen4_exp`) |
| | **`GatedDeltaNet` (GDN)** | Линейное рекуррентное внимание с матрицей состояния фиксированного для данной конфигурации размера (например, ~3 МиБ на слой), обновляемой за $O(1)$ по длине контекста на каждом токене вместо растущего KV-кэша. | `qwen3_next`, `qwen3_5_dense`, `qwen3_5_moe`, `Qwen3.8-Flash-Next` |
| **Преобразование каналов (FFN)** | **`DenseMlp`** | Плотный полносвязный блок (`SwiGLU` или `GeGLU`). | `Llama`, `Qwen3`, `qwen3_5_dense`, `Gemma 4` |
| | **`MoE` (Mixture of Experts)** | Смесь экспертов: роутер выбирает `top-k` экспертов из банка весов, плюс опционально работает общий эксперт (`Shared Expert`). Исполнение на CPU — один из вариантов размещения при подготовке. | `Qwen3-MoE`, `qwen3_next`, `qwen3_5_moe`, `Qwen3.8-Flash-Next`, `Gemma 4 26B-A4B`, `gpt-oss` |
| **Адаптеры и остаточные связи** | **`PLE` (Per-Layer Embeddings)** | Таблица послойных эмбеддингов или n-грамм, индексируемая по ID токенов. Хранение на NVMe требует явной выборки строк, декодирования и доставки потребителю. | `Gemma 4 E2B/E4B`, `Qwen3.8-Flash-Next` |
| | **`HyperConnections`** | Многопоточная остаточная связь (4 параллельных потока `residual`, смешиваемых перед каждым подблоком). | `Qwen3.8-Flash-Next` |

Подготовка проверяет операции, размеры, типы, раскладки и изменения состояния через реестр бэкендов. K и V — роли входов: общий ресурс или восстановление K из V описываются в графе, без автоматического выделения пары кэшей. Передачи и преобразования представлений входят в план. Неподдержанный путь отклоняется до исполнения либо заранее размещается на другом разрешённом устройстве; скрытого перехода на CPU нет. Добавление бэкенда для этих операций не требует менять описание семейства.

## 2. Сводная таблица семейств моделей

| Семейство | Требуемые модули и параметры |
| :--- | :--- |
| **`Llama`, `Qwen3`** | Базовый плотный путь: `FullAttention` + `DenseMlp` (`SwiGLU`) + `RMSNorm` + `RoPE`. |
| **`Qwen3-MoE`** | `FullAttention` + банк экспертов `MoE` (маршрутизация `softmax → top-k`). |
| **`qwen3_next`** | Гибрид 3:1 `GatedDeltaNet` (слитые проекции `in_proj_qkvz`/`ba` по $K$-группам) + `Gated Attention` (`q_proj` удвоенной ширины с выходным $\sigma$-гейтом), `zero-centered RMSNorm` (`1 + w`), `RMSNormGated`, `MoE` с `shared_expert_gate`, частичный 1D RoPE 0.25, `MTP`. |
| **`qwen3_5_dense`** (`qwen3_5`) | Гибрид 3:1 `GatedDeltaNet` (раздельные `in_proj_{qkv,z,b,a}`) + `Gated Attention`, плотный `DenseMlp` на каждом слое, `zero-centered RMSNorm`, чередующийся трёхмерный `M-RoPE` `[11, 11, 10]` (partial 0.25), `ViT` с осевым 2D RoPE, `MTP` (например, `Qwen3.8-27B`: 64 слоя 48:16, hidden 5120). |
| **`qwen3_5_moe`** | Гибрид 3:1 `GatedDeltaNet` (раздельные проекции) + `Gated Attention`, `MoE` (маршрутизируемые эксперты + общий эксперт с `shared_expert_gate`), `M-RoPE`, `ViT`, `MTP`. |
| **`gpt-oss`** | Обучаемые синки внимания, чередование `sliding`/`full` по `layer_types`, `YaRN`, `SwiGLU` с ограничением 7.0 (`clamp`), `bias` в проекциях, чат-формат `Harmony`. |
| **`Qwen3.8-Flash-Next`** (`qwen4_exp`) | Надстройка над `qwen3_next` / `qwen3_5_moe`: разреженное внимание `QSA` в full-слоях, `Hyper-Connections`, таблица n-грамм `PLE`, `MTP`, `M-RoPE`, `ViT`. |
| **`Gemma 4`** | Реконструкция $K = V$, пропорциональный `p-RoPE`, общий KV-кэш финальных слоёв, `PLE`, плотный MLP параллельно с MoE (у `26B-A4B`), бесбашенная мультимодальность у `12B`. |

## 3. Мультимодальные энкодеры

| Схема | Модели | Устройство энкодера |
| :--- | :--- | :--- |
| **Энкодер-башня (`vision-tower`, `audio-tower`)** | `qwen3_5_dense`, `qwen3_5_moe`, `Qwen3.8-Flash-Next`: ViT на 27 блоков (осевой 2D RoPE), hidden 1152, патч 16, слияние $2 \times 2 \to$ hidden декодера, видео с временным патчем 2.<br/>`Gemma 4 26B / 31B`: ViT на 27 слоёв, hidden 1152.<br/>`Gemma 4 E2B / E4B`: ViT на 16 слоёв; аудио — Conformer на 12 слоёв с чанковым вниманием. | Двунаправленное внимание без KV-кэша; выполняется один раз на изображение или аудиофрагмент с кэшированием выхода по хэшу содержимого. |
| **Прямая проекция патчей (без башни энкодера)** | `Gemma 4 12B` (`Gemma4Unified…`) | Изображение нарезается на патчи $48 \times 48$: `LayerNorm → Linear 6912 → 3840 → LayerNorm → + раздельные позиционные эмбеддинги по x и y → LayerNorm → RMSNorm → Linear` (до 280 токенов на картинку). Аудио — кадры по 640 отсчётов (40 мс при 16 кГц) `→ RMSNorm → Linear 640 → 3840` (до 750 токенов). Дальнейшую обработку выполняет сам декодер. |
